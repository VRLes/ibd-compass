## 🐛 Debugging notes — what went wrong and why

**Problem — recurring "Unexpected token" build errors on multi-line JSX**
Three separate times this session, pasting a multi-line JSX block (a TypeScript generic split across lines, and two `<a>` tags with attributes each on their own line) caused a Turbopack parse error pointing at a `>` a few lines below the actual issue. Root cause was never conclusively identified — copy-button use was confirmed, ruling out manual text-selection artifacts, and "Format On Paste" was confirmed off in VS Code settings.

**Fix:** collapsing the affected JSX onto fewer lines (attributes on one line rather than one-per-line) resolved it every time. No underlying code logic was ever wrong — purely a paste/parse quirk.

**Lesson:** if a build error says "Unexpected token" pointing at a `>` with no obvious cause nearby, try collapsing the surrounding multi-line JSX tag onto a single line before investigating further — this has now happened three times with the same fix working each time.

**Problem — Ctrl+F "no results" in VS Code**
Turned out to be focus-related, not a broken shortcut: the terminal panel (running `npm run dev`) had focus, so `Ctrl+F` triggered "Terminal: Find" instead of the editor's Find. Confirmed via the Keyboard Shortcuts panel that `Ctrl+F` is bound to multiple commands, each scoped to a different focus context (editor, terminal, notebook, etc.) — not a real conflict.

**Lesson:** click directly into the code editor pane before using `Ctrl+F`. `Ctrl+G` (Go to Line) is a reliable fallback regardless of focus.

**Lesson:** If curl output shows the same page hash after multiple pushes, go straight to Vercel dashboard → Deployments → Redeploy → uncheck cache. Don't keep pushing commits hoping it'll clear itself.
